# Vistora 全站 UI 审计（2026-09-05）

## 结论

本轮检查覆盖 29 个可访问路由模板，并补充 820px 中等宽度响应式复验。视觉语言本身已经具备鲜明的编辑台气质；主要问题集中在导航语义、加载状态和信息层级，而不是需要推翻品牌风格。

本轮已完成以下修改：

- 在 768–991px 区间保留侧栏名称，避免只显示 `01–07` 的猜谜式导航；
- 为创作首页设置可控的语义换行，并将路径标签统一为中文业务词汇；
- 将频道、素材、项目与 Skill 详情的空白/黑块加载态统一为有标题、有说明、有结构的加载骨架；
- 提高浅色主题辅助文字对比度，并统一圆角、边框与标题字距；
- 所有加载组件继续保留 `aria-busy`、`aria-live` 与屏幕阅读器标题。

## 主要视觉发现

1. **中等宽度导航失去语义**：旧样式在 991px 以下隐藏模块名，只留下编号。编号可以做辅助索引，但不能承担唯一导航信息。
2. **加载态被误读为故障**：频道页曾显示整块黑色矩形，Skill 页曾显示三个没有任何提示的空白卡片。用户无法判断是加载、空数据还是渲染失败。
3. **英文标签缺少体系**：`GENERATED`、`WEB CAPTURE`、`LOCAL PILOT`、`INDUSTRY` 与中文标题混排，但没有稳定的层级或翻译规则。
4. **长标题在临界宽度断句不自然**：创作首页标题可能在“变 / 成”之间断开；现已按语义在逗号后换行。
5. **浅色主题辅助文本偏淡**：说明、时间和状态备注在网格背景上对比不足，长页面阅读疲劳。
6. **执行与详情页技术信息较多**：保留真实审计数据是正确的，但应该始终让任务状态、下一步和最终产物优先于 ID、Provider 字段及原始摘要。本轮先通过共享层级和排版约束改善；后续可继续把低频技术字段收进“技术详情”披露区。

## 后续建议

- 将执行详情中的 Provider、版本 UUID、原始 JSON 默认折叠，面向运营用户只展示“状态 / 下一步 / 证据 / 产物”；
- 为中英文微文案建立正式规则：中文负责业务含义，英文只用于稳定的产品域标签；
- 下一轮补做 390px、768px、1440px 三档视觉回归，并把关键页截图纳入 CI；
- 旧版登录与产品页仍使用另一套版式，发布前应明确它们是营销入口还是兼容入口，避免双设计系统长期并存。
