# 无素材自动补材与编辑草案：产品链路与扩展计划

## 当前视频生成通路

| 模式 | 画面来源 | 主链路 | 发布语义 |
| --- | --- | --- | --- |
| 标准生产 | 已分析、已授权素材库 | 研究 →（可选清点）→ 写稿/配音 → 检索 → EDL → FFmpeg → 质检 | 素材和权利证据完整后可作为成片审核 |
| 无素材自动补材（默认） | 经来源证据验证的外部素材 | 自动建立私有补材库 → 实时清点 → 写稿/配音 → 按缺失 Beat 检索/下载 → 安全与版权分析 → 自动恢复重匹配 → EDL/FFmpeg → 质检 | 只有权利、分析和语义覆盖均通过的素材才能进入成片 |
| 无素材编辑草案 | 程序化编辑卡片 | 研究 → 无素材清点 → 写稿/配音 → 视频计划＋临时卡片 → 同一 EDL → 同一 FFmpeg → 强制复核 | 只能作为可播放、可替换画面的草案，不是可发布成片 |
| 部分缺口混剪草案 | 已授权真实素材＋缺口编辑卡片 | 保留已命中 Beat → 只为未命中 Beat 生成卡片 → 合并候选清单 → 同一 EDL/FFmpeg → 强制复核 | 可验证真实镜头与整体节奏，但所有占位 Beat 仍须替换 |
| Full-AI | 专用付费生成 Provider | 专用报价/授权 → 生成审计 → EDL → FFmpeg → 质检 | 独立端点、成本上限和 AI 披露 |
| 网页视频 | 用户批准的精确网页截图 | URL 安全检查 → 截图审核 → 固化/分析 → EDL → FFmpeg → 质检 | 只有获批截图能进入后续步骤 |

## 默认无素材链路

标准 Web 创作入口默认启用自动补材，只选择 Wikimedia 公版来源和
`public_domain` 许可策略。用户不需要预先创建或选择素材库：Control API 会在工作区内
创建或复用 slug 前缀为 `auto-acquired-footage` 的私有库，并把库 ID 固化到 Run 快照中；
若同名库已归档，会使用带顺序后缀的新库，避免无素材链路永久失效。
启用自动补材的单 Run 使用实时目录，不冻结创建时为空的目录快照；批量生产仍禁止逐
Run 联网补材并继续使用冻结快照，以保持成本和复现边界。

`media.inventory` 可以在实时空目录上成功输出 `pending_auto_acquisition`，让写作继续形成
结构化 Beat。`media.retrieve` 只查询缺失 Beat，导入素材后等待恶意扫描、版权、视觉和
片段分析；同一 acquisition group 完成后由既有恢复机制重跑检索。供应商未配置、暂时
不可用、权利证据不合格、分析失败或最终语义仍不匹配时会明确失败或进入审核，不会把
不合格画面送入渲染。

API 调用方仍须显式授权来源与许可策略：

```json
{
  "video_settings": {
    "asset_acquisition": {
      "enabled": true,
      "sources": ["wikimedia"],
      "max_assets": 3,
      "copyright_status": "public_domain",
      "rights_confirmed": false
    },
    "no_asset_draft": { "enabled": false }
  }
}
```

该 `false` 只在“Wikimedia + public_domain”组合下有效，因为 Provider 会逐文件验证
Commons 公版证据；YouTube、Bilibili 的“可以访问”不等于“可以使用”，不会作为新建
任务的默认来源，只有用户主动选择并确认适用许可时才进入采集计划。

## 可选编辑草案的成功定义

成功不是“把空白画面冒充成片”，而是同时满足：

1. 生成可播放 MP4，旁白、字幕、镜头时间轴完整；
2. 生成 `video-plan.json`，逐 Beat 记录解说、视觉意图、临时卡片和替换状态；
3. 临时画面以真实 `asset` 产物进入既有候选清单、素材选择和 EDL 血缘；
4. 项目页明确显示“无素材编辑草案”；
5. 质检始终加入 `editorial_draft_requires_material_replacement` 风险并等待人工复核，服务端拒绝批准仍含占位画面的质量步骤；
6. 不发起外部下载、不产生生成式视觉费用，也不声称临时卡片满足语义素材覆盖。

程序化卡片按确定性调色板复用，单 Run 最多发布 8 个图片对象；Beat 数量增长只增加候选行和视频计划行，不再线性增加占位图片对象。

项目页的“选择素材并重剪”会打开标准创作页，复用原主题、Skill、Pipeline、配音、渲染与视频规格，要求至少选择一个真实素材库，并强制关闭无素材降级。它创建新的不可变 Run，原草案保留为审计和对照依据。

编辑草案不是默认无素材策略。只有用户主动开启时，API 调用方才提交：

```json
{
  "video_settings": {
    "no_asset_draft": { "enabled": true }
  }
}
```

关闭自动补材和编辑草案后保持 fail-closed 行为：必需素材库未选择或没有覆盖时停止执行。

## 成功率指标

上线后应按模式分桶，避免用草案成功掩盖正式成片失败：

- `draft_start_rate`：无素材 Run 中成功进入写稿的比例；
- `auto_library_provision_rate`：无素材 Run 成功创建或复用私有补材库的比例；
- `acquisition_query_coverage_rate`：缺失 Beat 中成功发起合规查询的比例；
- `asset_analysis_pass_rate`：下载素材通过安全、版权和内容分析的比例；
- `auto_resume_success_rate`：分析完成后自动恢复并覆盖全部必需 Beat 的比例；
- `no_material_final_render_rate`：初始无素材 Run 最终使用真实合规素材完成渲染的比例；
- `draft_render_rate`：成功产出可解码 MP4 与 `video-plan.json` 的比例；
- `timeline_integrity_rate`：音频、字幕、Beat 与 EDL 时长门禁通过率；
- `material_replacement_rate`：草案后来完成真实素材替换的比例；
- `publish_conversion_rate`：经替换和最终复核后成为可发布版本的比例；
- `false_final_rate`：草案被误认作最终成片的比例，目标必须为 0；
- P50/P95 总时延、每分钟视频的 CPU 时间、对象存储增量与失败重试次数。

## 下一阶段扩展顺序

1. **补材预算与配额**：增加工作区/Provider 每日下载量、费用、并发、超时与熔断策略，并在创建前给出真实估算。
2. **Beat 级增量替换**：只重跑受影响的检索、时间线、渲染和质检；当前恢复可重跑素材步骤，但完整派生 Run 仍会执行整个 Pipeline。
3. **来源插件化**：统一 Provider 的搜索、许可证据、下载和速率限制契约；新来源不能绕过 SSRF、版权和恶意文件扫描。
4. **模板化程序画面**：编辑草案增加引用卡、数据卡、章节卡、地图/时间轴等受控模板；模板版本、字体许可和品牌变量进入 Run 快照。
5. **可选生成视觉**：由用户主动升级到 Full-AI；先报价、设成本上限和供应商并发限制，不在标准自动补材中隐式扣费。
6. **可观测性与容量**：按 Provider、查询、画幅和时长记录召回率、自动恢复率、队列深度、失败码、下载与 FFmpeg 资源消耗。

## 已知边界

- 程序化卡片只承担结构、节奏和字幕校验，不能证明视觉语义匹配；
- 自动补材依赖真实 Provider、网络、配额与可核验许可，不承诺任意题材都能找到合格素材；
- 当前标准 Run 的实时补材目录不是创建时冻结的目录快照，可复现性依赖候选清单、来源证据、导入文件哈希和最终 EDL；
- 当前没有“替换某一 Beat 素材并增量重渲染”的控制 API；替换入口通过派生完整新 Run 保持快照与审计语义清晰；
- 当前产品没有独立的对外发布端点；现有最终批准入口已在服务端校验 `replacement_required`，未来新增发布端点时仍必须复用同一门禁；
- 外部 TTS、研究 Provider、FFmpeg、数据库和对象存储仍须真实配置；该模式只解决画面素材为零，不替代其他基础设施。
